## 1. イントロダクション：なぜGitHubを学ぶのか（10分）

### GitHubとは

GitHubは、**Gitベースのバージョン管理プラットフォーム**です。  
かんたんに言うと、「チームでコードを書くときに、みんなの変更をうまく管理してくれるWebサービス」です。世界中の開発者が日常的に使っています。

### GitHubが重要な理由

- 🌍 **1億人以上の開発者**が利用する世界最大のプラットフォーム
- 🏢 企業の開発現場で**事実上の標準ツール（デファクトスタンダード）**
- 🤝 **チーム開発**に欠かせないツール
- 📝 コードだけでなく**ドキュメント管理**にも使える
- 🤖 **CI/CD（テストやデプロイの自動化）** の基盤

## 2. GitHubアカウント作成 & 初期設定（15分）

### 2.1 アカウント作成

1. [https://github.com](https://github.com) にアクセス
2. **Sign up** をクリック
3. 次の情報を入力します：
   - メールアドレス
   - パスワード
   - ユーザー名（他の人から見えるあなたの名前）
4. メール認証を完了させる

> 💡 **ユーザー名のコツ**: ユーザー名はプロフィールURL（`github.com/ユーザー名`）の一部になります。あとから変更もできますが、覚えやすくてわかりやすい名前にしておくとよいでしょう。

### 2.2 プロフィール設定

1. 右上のアイコン → **Settings** をクリック
2. **Public profile** で以下を設定：
   - **Name**：表示名
   - **Bio**：自己紹介
   - **Profile picture**：アイコン画像

### 2.3 二要素認証（2FA）の設定

アカウントを安全に守るために、二要素認証（ログイン時にスマホなどで追加確認する仕組み）を設定します：

1. **Settings** → **Password and authentication**
2. **Two-factor authentication** の **Enable** をクリック
3. 認証アプリ（Google Authenticator など）を使って設定

> ⚠️ **重要**: 2FAのリカバリーコード（復旧用のコード）は、スマホを紛失したときに必要です。安全な場所にメモしておいてください。

### 2.4 Git（ローカル環境）の準備

#### Gitのインストール

**🪟 Windows の場合：**

1. [https://git-scm.com/downloads/win](https://git-scm.com/downloads/win) からインストーラーをダウンロード
2. インストーラーを実行（デフォルト設定でOK）
3. インストール後、**PowerShell** または **Git Bash** を開いて確認

**🍎 Mac の場合：**

1. ターミナルを開いて以下を実行（Xcode Command Line Toolsに含まれる）：
   ```bash
   xcode-select --install
   ```
2. または [https://git-scm.com/downloads/mac](https://git-scm.com/downloads/mac) からインストール
3. Homebrewを使う場合：
   ```bash
   brew install git
   ```

#### Gitの初期設定

ターミナルを開いて以下を実行します：

- **🪟 Windows**: PowerShell または Git Bash を使用
- **🍎 Mac**: ターミナル.app を使用

```bash
# Gitがインストールされているか確認
git --version

# ユーザー名とメールアドレスを設定
git config --global user.name "あなたの名前"
git config --global user.email "あなたのメールアドレス"

# 設定を確認
git config --list
```

> 💡 上記コマンドはWindows（PowerShell / Git Bash）でもMac（ターミナル）でも共通です。

## 3. ソフトウェア開発サイクルの全体像（15分）

### 3.1 開発サイクルとは

ソフトウェア開発は、一度作って終わりではなく、以下のステップを繰り返しながら進めていきます：

```
┌─────────────────────────────────────────────────┐
│                                                   │
│    計画 → 開発 → レビュー → テスト → リリース    │
│     ↑                                     │      │
│     └─────────── フィードバック ───────────┘      │
│                                                   │
└─────────────────────────────────────────────────┘
```

### 3.2 各フェーズの概要

| フェーズ | 内容 | GitHubの機能 |
|----------|------|-------------|
| **計画** | 何を作るか決める、タスク管理 | Issue, Project |
| **開発** | コードを書く、変更を管理 | Repository, Branch, Commit |
| **レビュー** | コードの品質を確認 | Pull Request, Code Review |
| **テスト** | 自動テスト、品質チェック | GitHub Actions |
| **リリース** | 本番環境へ反映 | Merge, GitHub Actions, Releases |

### 3.3 GitHubが開発サイクルをどう支えるか

GitHubでは、以下のような流れで開発を進めます。それぞれの機能がどのステップに対応するか見てみましょう：

```
 Issue（課題を作成）
   ↓
 Branch（作業用ブランチ作成）
   ↓
 Commit（変更をコミット）
   ↓
 Pull Request（レビュー依頼）
   ↓
 Code Review（コードレビュー）
   ↓
 GitHub Actions（自動テスト実行）
   ↓
 Merge（本流に統合）
   ↓
 Deploy / Release（リリース）
```

### 3.4 従来の開発 vs GitHub を活用した開発

GitHubを使うと、これまで手作業だった多くの作業が効率化されます。

| 項目 | 従来の方法 | GitHubを活用 |
|------|-----------|-------------|
| ファイル管理 | フォルダ名で区別（v1, v2...） | Gitで変更履歴を自動管理 |
| コード共有 | メール、USBメモリ | Repository（リポジトリ）で共有 |
| タスク管理 | Excelやホワイトボード | Issue & Project |
| コードレビュー | 印刷して確認 | Pull Request でオンラインレビュー |
| テスト・ビルド | 手動で実行 | GitHub Actions で自動化 |

## 4. Gitの基本概念（15分）

### 4.1 Gitとは

**Git**は、**分散型バージョン管理システム**です。  
「バージョン管理」とは、ファイルの変更履歴を記録して、「いつ・誰が・何を変えたか」をたどれるようにすることです。

> 💡 **Git ≠ GitHub**（よく混同されますが、別物です！）  
> **Git** = ファイルの変更履歴を管理するツール（自分のパソコンで動く）  
> **GitHub** = Gitを活用してチームで協力するためのクラウドサービス

### 4.2 バージョン管理の基本

バージョン管理では、変更のたびに「セーブポイント（Commit）」を作ります。ゲームのセーブデータのように、好きな時点の状態に戻れるのが大きなメリットです。

```
時間軸 →

Commit 1      Commit 2      Commit 3      Commit 4
   │             │             │             │
   ▼             ▼             ▼             ▼
┌──────┐    ┌──────┐    ┌──────┐    ┌──────┐
│初期   │    │機能A  │    │バグ修正│    │機能B  │
│作成   │───▶│追加   │───▶│      │───▶│追加   │
└──────┘    └──────┘    └──────┘    └──────┘
```

### 4.3 覚えておきたい用語

| 用語 | かんたんな説明 |
|------|------|
| **Repository（リポジトリ）** | プロジェクトのファイルと変更履歴をまとめて保存する場所。「プロジェクトフォルダ」のようなもの |
| **Commit（コミット）** | 変更のスナップショット。ゲームでいう「セーブポイント」 |
| **Branch（ブランチ）** | メインのコードに影響を与えずに、別の作業をするための「枝分かれ」 |
| **Merge（マージ）** | 枝分かれした作業を本流に合流させること |
| **Clone（クローン）** | GitHub上のリポジトリを自分のパソコンにまるごとコピーすること |
| **Push（プッシュ）** | 自分のパソコンでの変更をGitHubに送ること |
| **Pull（プル）** | GitHubの最新の変更を自分のパソコンに取り込むこと |

### 4.4 リモートとローカルの関係

GitHubでは、「GitHub上（リモート）」と「自分のパソコン（ローカル）」の2か所にリポジトリがあります。この2つを同期しながら開発を進めます。

```
┌──────────────────────────────┐
│        GitHub（リモート）      │
│    ┌──────────────────┐      │
│    │   Remote Repository │    │
│    └────────┬─────────┘      │
└─────────────┼────────────────┘
              │
         push ↑ ↓ pull/clone
              │
┌─────────────┼────────────────┐
│     あなたのPC（ローカル）      │
│    ┌────────┴─────────┐      │
│    │  Local Repository  │     │
│    └──────────────────┘      │
└──────────────────────────────┘
```

### 4.5 基本的なGitコマンド

以下は、よく使うGitコマンドの一覧です。  
**Windows（PowerShell / Git Bash）** でも **Mac（ターミナル）** でもすべて同じコマンドです。

```bash
# リポジトリの作成
git init

# リモートリポジトリのコピー
git clone <URL>

# 変更の確認
git status

# 変更をステージング
git add <ファイル名>
git add .          # すべての変更をステージング

# コミット
git commit -m "変更内容の説明"

# リモートに送信
git push

# リモートから取得
git pull
```

### ✅ ハンズオン：Gitの基本操作

**🪟 Windows（PowerShell）の場合：**

```powershell
# 1. テスト用フォルダを作成
mkdir git-practice
cd git-practice

# 2. Gitリポジトリを初期化
git init

# 3. ファイルを作成
echo "Hello, Git!" > hello.txt

# 4. 状態を確認
git status

# 5. ステージングに追加
git add hello.txt

# 6. コミット
git commit -m "最初のコミット: hello.txtを追加"

# 7. 履歴を確認
git log
```

**🍎 Mac（ターミナル）の場合：**

```bash
# 1. テスト用フォルダを作成
mkdir git-practice
cd git-practice

# 2. Gitリポジトリを初期化
git init

# 3. ファイルを作成
echo "Hello, Git!" > hello.txt

# 4. 状態を確認
git status

# 5. ステージングに追加
git add hello.txt

# 6. コミット
git commit -m "最初のコミット: hello.txtを追加"

# 7. 履歴を確認
git log
```

> 💡 この例ではWindows/Macで手順はほぼ同じです。主な違いはターミナルアプリの起動方法です。  
> **Windows**: スタートメニュー → PowerShell（または Git Bash）  
> **Mac**: Spotlight（⌘+Space）→ 「ターミナル」
